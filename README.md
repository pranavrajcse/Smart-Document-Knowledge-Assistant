# Smart Document Knowledge Assistant

A Retrieval-Augmented Generation (RAG) app that answers questions from your own PDF and TXT files.
Built for NEXUS TECH RECRUITMENT 2026 - Project 02.

## Problem Statement

Finding a specific answer inside long notes, reports or PDFs is slow. General chatbots can answer
questions, but they may invent facts that are not in your documents.

## Objective

Build a chat assistant that answers questions **only from the documents the user uploads**, and shows
the exact text snippets used so the answer can be verified.

## Features

- Upload one or multiple PDF/TXT files
- Text extraction (PDF page numbers are kept)
- Overlapping text chunking
- Local embeddings with `sentence-transformers/all-MiniLM-L6-v2`
- FAISS similarity search (top 5 chunks by default)
- Answers generated by Google Gemini, restricted to the retrieved chunks
- Chat interface with follow-up questions (recent chat turns are sent to Gemini)
- Expandable **Sources** under every answer: filename, page/chunk, retrieved text
- List of loaded documents, a "Use sample notes" button and a clear/reset button
- Friendly handling of: no files, unsupported file, empty document, PDF read failure, missing API key, Gemini errors

## Tech Stack

Python, Streamlit, pypdf, sentence-transformers, FAISS (faiss-cpu), Google Gemini API (`google-genai`), python-dotenv.

## RAG Architecture

```text
PDF/TXT -> Text extraction -> Chunking -> Embeddings -> FAISS
                                                          |
Question -> Embedding -> Similarity search -> Top 5 chunks
                                                          |
                              Gemini (question + chunks only)
                                                          |
                                                   Answer + Sources
```

## How It Works

1. **Extract** - text is read from each uploaded file (`pypdf` for PDFs).
2. **Chunk** - text is split into ~800-character pieces with 150 characters of overlap. Each chunk stores its filename, page, chunk number and text.
3. **Embed** - each chunk becomes a vector using the local MiniLM model.
4. **Index** - vectors are stored in a FAISS index.
5. **Retrieve** - the question is embedded and the 5 most similar chunks are found.
6. **Generate** - only the question, recent chat history and those chunks are sent to Gemini, with instructions to answer only from the context and to reply "I couldn't find this information in the uploaded documents." otherwise.
7. **Show sources** - the retrieved chunks are displayed under the answer.

## Installation

```bash
cd smart-document-knowledge-assistant
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

The embedding model (~90 MB) is downloaded automatically the first time you load a document.

## Gemini API Key Setup

1. Create a key at https://aistudio.google.com/apikey
2. Copy the example file: `cp .env.example .env` (Windows: `copy .env.example .env`)
3. Edit `.env`:

```text
GEMINI_API_KEY=your_real_key
GEMINI_MODEL=gemini-3.8-flash
```

`GEMINI_MODEL` can be any Gemini model your key can access. If it is left as the placeholder, the app falls back to `gemini-3.8-flash`.
The `.env` file is ignored by git and the key is never shown in the app. The app starts without a key; you can add it later and just ask again.

## How to Run

```bash
streamlit run app.py
```

Open the URL shown in the terminal (usually http://localhost:8501).
Click **Use sample notes** or upload your own files, then start chatting.

With `data/sample_notes.txt`:

- What is machine learning?
- What is supervised learning?
- What is unsupervised learning?
- What is classification?
- What is regression?
- What is overfitting?
- What is a feature?
- Follow-up: "Give me an example of that."

## Limitations

- Scanned (image-only) PDFs are not supported because there is no OCR.
- Fixed-size chunking can split a topic across chunks.
- The index lives in memory and is rebuilt when you reload the page; nothing is saved to disk.
- Follow-up retrieval is simple: very short questions are searched together with the previous question.
- Answer quality depends on the retrieved chunks and on Gemini.
- Tables and images inside PDFs are not interpreted.

## Future Improvements

- OCR for scanned PDFs
- Sentence-aware or heading-aware chunking
- Saving the FAISS index to disk
- Support for DOCX and other formats
- Re-ranking of retrieved chunks
- Streaming answers
